# Supporting data: verification after a contributor handoff

This document supports the [live study page](README.md). **Results are in
progress.** The current design is specified in
[`DECISIONS.md`](../../experiments/verification_pilot/DECISIONS.md); scripted
runs check the fixture and plan but supply no live model observation.

## Method

The source is the pinned 62-file Oakridge workflow slice. Four G3 type
renames have respectively 20, 18, 10, and 8 whole-word use-site files, each
split across three owners with at least two files per owner. The new spellings
do not occur in the raw slice. The 16 base subjects consist of three
single-remnant owner cases and one clean control per rename. Native and quoted
presentation of each remnant case gives 24 active sessions per model route.
`CHANGELOG.md` and `docs/migration.md` are planted only in generated subject
workspaces as historical decoy carriers.

A session has T1, T2, and T3 turns and one declared judge. The snapshot also
retains deferred tier arms and the four clean controls, but the current plan
excludes those coordinates. The model-free scripted run checks that all 24
active coordinates close and produce one verdict each. It is not evidence of
model behavior.

## Qualification and reporting

The [smoke rule](../../experiments/verification_pilot/SMOKE.md) requires manual
review of the 12-cell live smoke on each route. For each route and arm, the
first-wide-search share counts only sessions whose first successful file
inspection is a repository-wide search for the migration's old symbol. If
that share exceeds 50%, escalation order, untouched remnants, and test
masking lead that route's interpretation.

The full 96-cell ceiling is a capacity bound across declared arms and base
subjects, not a commitment to execute deferred coordinates. Results and costs
remain pending until a route passes qualification and its exported records
are verified. Route reports must remain separate because model identity is
part of the authorized runtime.
